# Plan 002: Seal the confidential eval data

**Status:** completed

## Goal

`eval/house_set.json` (135 question/answer pairs from five named customers'
questionnaires) and `eval/answer_memory.json` (698 of the team's real answers)
exist in the repository only encrypted. Anyone with the key in their `.env`
unlocks them to their usual paths and every evaluation and script runs
unchanged; without the key the repository still works and `check` still
passes; and the plaintext cannot be committed again without a check failing.
Decided by the user on 2026-10-05 (D-005): key held in `.env`, encrypting
forward only, no history rewrite.

## Acceptance criteria

- [x] `eval/sealed/house_set.json.enc` and `eval/sealed/answer_memory.json.enc` are committed, encrypted with AES-256-GCM (the `cryptography` package), the file name bound in as associated data. The plaintext paths are gitignored and removed from the index; the files stay on disk.
- [x] `EVAL_DATA_KEY` is a setting in `src/config.py`, listed with an empty value in `.env.example` and in `docs/generated/settings.md`.
- [x] `uv run poe eval-unlock` decrypts to the usual paths and `uv run poe eval-seal` re-encrypts (only what changed); `uv run poe eval-status` reports each file's state. A wrong, malformed or missing key, or a tampered file, fails with a message and a FIX line, and writes nothing. Unlock refuses to overwrite a local copy that differs from the sealed one unless forced.
- [x] The key is generated by a command that writes it into `.env` and never prints it; no output or error message contains the key (tested).
- [x] An `arch` rule, ARCH-SEALED, fails when a sealed file's plaintext is in the git index, or when a local plaintext differs from its sealed copy (by SHA-256 recorded in a manifest, so the check needs no key).
- [x] Without unlocked data, the two tests that read the real house set skip with a reason that says how to unlock, and the loaders in `eval/house.py` raise an error that says the same.
- [x] Round trip verified on the real files: seal, unlock into a scratch directory, byte-identical to the originals.
- [x] `uv run poe check` passes; `SECURITY.md`, TD-013, GP-16, `CLAUDE.md` and the README's evaluation section are updated.
